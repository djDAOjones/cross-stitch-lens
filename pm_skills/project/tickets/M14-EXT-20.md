# M14-EXT-20 — Design size, scale and the free-aspect default

Memo items 2, 3 and 7 (fourth look, D106). Reworks the shape D101
signed — on the owner's own authority, weeks-not-months later, so the
supersession is deliberate and named, not drift.

## Outcome

Three moves that make the region↔design coupling legible:

1. **"Lock aspect", default off.** The session toggle currently
   labelled `Aspect follows design` (default pressed, D101) renames to
   "Lock aspect" and defaults **off**. Off means the region's shape
   drives the design; on restores the D52 conduct whole
   (`constrainRect` the only route; region chooses which pixels, never
   how many stitches). Session-only remains: the reset state each
   session is now *unlocked*.
2. **Drags rederive both dimensions through a visible scale.** D101's
   one-direction derive (shape → height, width stays the user's) is
   superseded: with the lock off, a region drag rederives **both**
   design width and height from the region size at a fixed
   **source-px-per-stitch scale**. A **scale slider** (label to pick at
   design time — candidates: "Detail", "Stitch size", "Source pixels
   per stitch") surfaces that ratio so the resolution consequence of
   dragging is visible while it happens.
3. **Compact Size fields.** The `Size` fieldset's width/height inputs
   shrink to a tighter footprint (e.g. one row, paired inputs with a ×
   separator) without losing visible labels or 44 px targets. The S1
   reparent (fields join the Capture region section during a session,
   D101) is unaffected.

## The coupling matrix (settle at the design gate)

Four inputs can now change geometry; each must name what it holds
fixed and what it rederives:

| User action | Holds fixed | Rederives |
| --- | --- | --- |
| Drag region (lock off) | scale (px/stitch) | design w & h |
| Move scale slider | region | design w & h |
| Edit design w or h field | region | scale (and the other dim only if lock forces aspect) |
| Drag region (lock on) | design w & h (D52) | nothing — region constrained |

The field-edit row is the open design question: editing stitch width
for a fixed region implies the scale moves. Whatever is picked, the
derive chain must stay a fixed point (no feedback loop) — the crop
suite already proves this for the D101 pair; extend it for the
two-dimension derive.

## Constraints

- Stitches stay square on every path — the scale is one number, never
  per-axis.
- The four-resolutions contract (D52) still splits on the toggle;
  `AGENTS.md` → "The four resolutions" carries D101's split text and
  must be rewritten to the new default and both-dims derive —
  a protected-doc edit: ledger it in `doc-deltas.md` at close, or
  update in-task with the owner's explicit OK, as D101 did.
- Derived fields stay mirrored and disabled-with-reason per D101's
  conventions (both fields now derive while unlocked, so the
  disable/helper treatment applies to both; the readout names the
  derivation).
- Status copy referencing the old label ("Aspect follows the design
  again.") updates with the rename.
- Grid caps (max 1024) clamp the derive; announce the clamp, never
  silently exceed.
- Keyboard route parity per D101: the toggle is the keyboard path to a
  free resize; shift-drag temporary free applies while locked.
