# M14-EXT-26 — Debug menu: copy, download, email

Memo item 10b (fourth look, D106): "include a debug button (we need
options to auto email dev, download json, and to copy json, maybe
these are submenu options)".

## Outcome

One labelled **Debug** control gathering the maintainer routes as a
small menu (or disclosure — the debug panel's `details`/`summary` is
the house pattern):

1. **Copy diagnostics JSON** — exists (`src/ui/diagnostics-button.ts`,
   "Copy diagnostics").
2. **Download diagnostics JSON** — exists ("Download log").
3. **Email the dev** — new: a `mailto:` link prefilled with subject
   (app version + build id) and a body carrying the redacted summary
   headline plus the instruction to attach the downloaded JSON —
   `mailto:` cannot attach files, so the flow is download-then-email
   and the copy says so. No network call; the app stays offline.

This consolidates the existing loose buttons into one surface rather
than adding a second diagnostics home. The existing debug timings
panel keeps its own disclosure unless consolidation is free.

## Rules that bind

Per UI-STANDARDS → "Diagnostics affordance" and DEV-INFRASTRUCTURE →
"Maintainer diagnostics":

- **Dev-only by default**; production exposure needs the explicit
  opt-in and a redaction review.
- **Redacted bundle only** — no secrets, tokens, storage dumps, PII.
  The email body gets the same redacted content or less, never more.
- **Visible text label** ("Debug"), accessible name identical; 44 px
  targets throughout the menu; keyboard operable; focus returns to
  the trigger on close.
- Every route announces its outcome programmatically (copy confirmed,
  download named, mail client handed off) — never a silent action.
- Menu anatomy per Carbon's menu-button pattern, implemented in
  project code.

## Open at design time

- The dev email address: hard-code the maintainer's, or leave a
  placeholder constant? (No secrets involved either way; it ships in
  a public bundle, so it is the owner's call which address to expose.
  Ask at the scope gate.)
- Whether the retired Preview focus slot (EXT-24) or the existing
  diagnostics placement hosts the Debug control.

## Files

`src/ui/diagnostics-button.ts` (grows into the menu),
`src/ui/debug-panel.ts` (unchanged unless consolidation is free),
`src/main.ts` (app bar placement), diagnostics bundle builder in
`src/` (email body reuses it).
