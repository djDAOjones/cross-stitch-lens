# M14-EXT-43 — Threads dropdown snaps shut: diagnose and fix

Memo item 7 (sixth look, D112): "the drop down for threads is
glitchy, and it closes before I can select. the dither drop down is
fine." A defect — run in bug mode (diagnosis first), before EXT-42
restructures the same panel.

## Hypothesis (recorded at triage, to verify first)

`client.setOnResult` calls `palettePanel.update(panelState())` on
**every processed frame** — during live capture that is ≥ 4×/second.
If `update()` rebuilds or replaces the source select (or its option
list) each time, an open native popup collapses under the pointer.
The control the owner names — **"Threads to choose from"** — has a
dynamic option list (brands / presets / library palettes), making it
the natural casualty.

The dither selects being "fine" is the confirming contrast: the
dither panel is deliberately rebuilt **only on algorithm change**
(`src/ui/dither-model.ts` design), so its popups never get yanked.

Likely co-victims once confirmed: the per-row rule selects, brand
checkboxes, and text inputs in the thread depth (a focused search
field losing its caret per frame would be the same class of bug —
check while in there).

## Repro to pin

Load any source (a still image suffices if `update()` also fires on
its frame results / applyPolicy passes — verify which triggers fire
without capture), open "Threads to choose from", wait ≤ 1 s. Under
live capture the window is tighter still.

## Fix shape (settle in diagnosis)

- Never rebuild a control that is focused or has an open popup; or
- Diff-update: fingerprint the option list (ids in order — the D46
  cache-key idiom) and touch the DOM only when it actually changed;
  update values/text in place otherwise. This is the better fix —
  it also stops per-frame DOM churn for every other control.
- The pure-model/DOM split in `palette-panel.ts` should make the
  fingerprint cheap; keep the model pure.

## Done when

A select stays open and selectable while frames process (verified
live with a forced frame cadence); a regression test pins
"unchanged state ⇒ no DOM rebuild" on the panel's update path; no
caret loss in the search field across updates.
