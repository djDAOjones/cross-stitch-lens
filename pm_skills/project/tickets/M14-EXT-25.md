# M14-EXT-25 — Capture session controls rationalised [sign-off]

Memo item 9 (fourth look, D106). The owner asked for a proposal, not
a prescription: "is there justification for capture frame, pause
capture, lock region and stop capture? … help come up with a good
solution here." Options-first; the pick is theirs.

## Outcome

The session button row earns its footprint or shrinks. Fixed point:
**Stop capture moves to the app bar** — the memo suggests it "could
become a state of the Source button, if that fits UI directives".

## The four controls, and what each is for

- **`Capture frame`** — single-frame grab; also the recovery route
  when the live pump dies (the app's own error copy says "Capture is
  still running — use Capture frame"). Cutting it removes that
  recovery; keeping it needs that story told.
- **`Pause capture`** — freeze/resume the live pump; named state per
  UI-STANDARDS ("paused" must be explicit). A candidate for merging
  with something rather than deletion.
- **`Lock region`** — freezes the crop rect against accidental drags;
  distinct from the aspect toggle (EXT-20's "Lock aspect"). Two
  "lock" labels in one section is a collision the recut must resolve
  regardless of what survives.
- **`Stop capture`** — ends the session. Moves to the app bar.

## Option axes for the proposal (shape at design time)

- **Stop in the bar:** (a) the Source button gains a session state
  (label/menu shows "capturing — stop"); (b) a separate Stop button
  appears in the bar only during a session. The Source-button route
  must not hide "switch source" behind the same click that stops.
- **Pause:** keep as-is / fold into the Source button's session menu /
  fold into the preview surface. Named-state rule holds wherever it
  lands.
- **Capture frame:** keep (recovery story intact) / demote to the
  session menu / cut (recovery re-routed or accepted as loss — owner
  must say so explicitly).
- **Lock region:** keep / merge conceptually with the region's own
  affordance (e.g. lock via the region overlay) / cut.

EXT-24 retires the Preview focus button first, freeing app-bar room —
run order matters and is already encoded in the backlog.

## Constraints

- Every surviving control: visible text label, 44 px target, state
  announced programmatically (a Source button that changes meaning
  must change its accessible name).
- No session function may vanish silently: each cut is named in the
  option pack and signed by the owner.
- Session states ("paused", "live update stopped") stay explicitly
  named per UI-STANDARDS.
