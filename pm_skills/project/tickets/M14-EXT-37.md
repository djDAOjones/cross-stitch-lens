# M14-EXT-37 — Full Carbon conformance review

Memo item 10 (fifth look, D109): "full IBM carbon review / check."

## What this is

A systematic conformance audit of every control and pattern against
IBM Carbon's **productive** design language — the reference standard
per UI-STANDARDS ("Carbon is not installed as a package; implemented
in project code to match Carbon's spec"). The check is against the
public Carbon specification (component anatomy, tokens, interaction
conventions), not package parity.

## Method (VERIFY-01's table discipline)

Build a conformance table, one row per component class in the app:

| Surface | Carbon reference | Checks |
| --- | --- | --- |
| Accordion sections | Carbon accordion | anatomy (h-wrapped button, chevron placement/direction, panel padding), states |
| Toggles (Threadify, Constrain, Only-owned, Serpentine) | Carbon toggle | track/thumb geometry, On/Off state text, disabled |
| Buttons (bar, strip ghosts, primaries, steppers) | Carbon button | kinds (primary/ghost), heights, padding scale, icon-free text rule |
| Number/text/search/select fields | Carbon text input / select | label/helper/error anatomy, field heights, focus/invalid states |
| Sliders (Colours, Stitch size, Split) | Carbon slider | label + value relationship, track sizing |
| Modals (Source, name prompt, danger, grid form) | Carbon modal | header/body/footer anatomy, action order/alignment, danger variant |
| Menu/disclosure (Debug, depth reveals) | Carbon menu / accordion | trigger anatomy, open placement |
| Data tables (colours by usage, thread rows) | Carbon data table | header row, density, zebra/rule conventions |
| Type & spacing | Carbon type ramp / spacing scale | every literal vs token (ui-spec §9), heading levels |
| Interaction states | Carbon states | hover/active/focus/disabled on every interactive class, both schemes |

Per row: **conforms** / **deviates — fix** / **deviates — waive with
reason** (the project has sanctioned deviations already: text
buttons over icon buttons per D50, AAA over AA per the hard rules —
those are re-affirmed, not re-litigated).

## Bounds

- Where Carbon's default meets AA but not this project's AAA, AAA
  wins (UI-STANDARDS: Carbon is the baseline, not the ceiling).
- Fixes are styling/anatomy only — behaviour changes route to their
  own tasks; findings too big to fix inline become backlog items.
- Runs **after** EXT-36 so the polish pass's changes are inside the
  audit, and conformance is checked on final surface.

## Done when

The table is complete over every component class; every deviation is
fixed or waived on record in `docs/ui-evidence.md`; the gate is
green; residue (if any) is named for ACCEPT-01.
