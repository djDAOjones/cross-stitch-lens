# M10 — Multi-page chart layout

## Outcome

Export patterns too large for one readable sheet as deterministic, print-safe
multi-page PDFs with repeated coordinates, controlled overlap, registration
marks, and enough context to assemble the full design without guessing.

## Current baseline

`pdfLayout` computes one A4/Letter page with portrait/landscape orientation,
margins, optional title, a capped thread key, and one aspect-fitted chart raster.
`buildChartPdf` adds exactly one page. The raster chart is built in full before
embedding and is constrained by the canvas-side limit. Page tiling, fixed cell
scale, overlap, registration, page numbers, overview/cover pages, and repeated
keys do not exist.

## Architecture boundary

Start with a pure page planner. Its inputs are stitch-grid dimensions, page
geometry, printer-safe margins, furniture sizes, cell-size/scale policy, overlap
in whole stitches, and key-placement policy. Its output is an ordered list of
page descriptors containing:

- global inclusive/exclusive stitch bounds;
- local chart box and physical scale;
- page row/column and human label;
- overlap edges and repeated coordinate ranges;
- marks, headers/footers, and key/overview placement.

Use half-open grid ranges internally to avoid duplicated or missing boundary
stitches. Define whether overlap stitches repeat on the next page and visually
mark the trim/join boundary. Page planning must be independent of canvas and PDF
I/O so hand-solvable layouts can be exhaustively tested.

## Scale modes

Do not mix incompatible promises. Provide an explicit choice among:

- fit to one page (current behaviour);
- fixed physical cell size or stitches per centimetre, deriving page count;
- fixed stitches per page, deriving the printable cell size.

Validate minimum legible symbol/grid size and printer-safe margins. If settings
leave no drawable grid or overlap consumes a page, return a specific error. A3
or custom sizes should be added only when the page model is generic, not as
special cases.

## Rendering strategy

Render each page's stitch slice at its own required resolution instead of making
one unbounded whole-chart raster and cropping it. Share global stitch/grid
coordinates so symbols, major divisions, and numbering agree at page edges.
Prefer vector PDF furniture and, after M9, vector/text symbols; raster colour
cells can remain acceptable if their effective DPI is recorded and print tests
pass. Keep exported output on the full-quality pipeline path.

The thread-key policy (`every page`, `once`, or cover/overview) and omitted-key
behaviour must be explicit. A page must identify project/title, page x of y, grid
range, orientation, and adjacent pages without exposing private source data.

## Likely implementation surface

New pure planner/types near `src/export/pdf.ts`, chart slice rendering, pdf-lib
page assembly, Pattern Export controls, project schema/migration, filenames,
diagnostics, and benchmark boundaries. M9 supplies symbol assignments; M11
supplies advanced print style. Keep those as inputs rather than coupling the
planner to UI state.

## Acceptance evidence

Test exact-fit, one-stitch overflow, portrait/landscape, wide/tall grids,
one-row/column, margin failure, every overlap edge, page order, no gaps, expected
duplicates only, global numbering, key policies, and save/load. Parse generated
PDFs to assert page count and dimensions. Rasterise/print representative pages,
join them physically, verify scale with a ruler, and inspect marks near real
printer non-printable areas.

Benchmark planning, per-page rendering, peak memory, PDF assembly, and file size
on a large supported grid. Do not weaken the global export limit without a
recorded decision.
