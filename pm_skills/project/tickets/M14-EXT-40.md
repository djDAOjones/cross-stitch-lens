# M14-EXT-40 — Design dissolves into Capture; Stitch size becomes Zoom; Stats gains the row

Memo item 5 (sixth look, D111): "remove the design section. moe
[move] the resolution integer controls to the capture section, above
or below stitch size. make stitch size named 'zoom' using a zoom
factor, and make stitch size an entry in stats."

Supersedes **D110's EXT-34/A** (Size's "one permanent home in
Design") on the owner's authority, one day after it shipped, having
seen it live. The reversal is bigger than S1's return: S1 moved the
fields per-session; this makes the Capture section their only home.

## The three gate questions

1. **No-session home.** The Capture section mounts only while a
   session runs (`showCaptureSection`/`hideCaptureSection`), so a
   still-image user would lose the size fields entirely.
   - **A (recommended): the Capture section becomes permanent** once
     a source exists — it holds Zoom + width × height always, and the
     session machinery (Stop · Freeze · locks · thumb · crop) shows
     only during a session (the hidden-dance returns for the session
     verbs, or a sub-group mounts). Naming tension: "Capture" over a
     still image is a stretch — settle the section title at the gate
     ("Capture", "Source & size", …); note D79's user-language rule.
   - B: fields join Stats. Rejected as recommendation — EXT-21 made
     Stats a readout by design; controls do not belong there.
   - C: keep a slimmed Design under another name. Contradicts the
     memo's explicit "remove".

2. **The Zoom factor.** Current `stitchSizePx` = source px per
   stitch (e.g. 3 = three source pixels make one stitch).
   - **(i) (recommended): factor = the same number, "Zoom 3×"** —
     helper names the meaning ("source pixels per stitch"); the
     number the owner has already calibrated survives the rename.
   - (ii) percentage: 100 / stitchSizePx ("33%" = source reduced to
     a third). Direction reads as shrink; sub-100 values for every
     real capture.
   - Slider bounds/step unchanged either way; the derive maths
     (`deriveGridSize`) is untouched — this is label + unit surface.

3. **The naming collision.** The preview already owns "zoom" (§1/§6
   vocabulary: Zoom in/out buttons, the strip's zoom % readout —
   preview CSS px per stitch). A second "Zoom" (capture px per
   stitch) puts two zooms one panel apart, exactly the single-name
   hazard the D52 four-resolutions contract exists to prevent. The
   owner's word is "zoom" — record the tension, disambiguate by
   helper/unit at minimum, and name it for ACCEPT-01 rather than
   silently renaming either.

## Stats row

"Stitch size" (or the gate's chosen word) joins Stats as a readout —
value + unit, updated with the derive; readout only (EXT-21's model
holds). Populated only while a capture session holds a region?
No — the ratio exists for any source once EXT-40/A makes the section
permanent; show it whenever it is defined.
