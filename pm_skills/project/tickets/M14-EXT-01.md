# M14-EXT-01 — Top bar consolidation

## Outcome

One app bar carrying: title · quiet build id · dev-only diagnostics
cluster (Copy diagnostics + Debug log with a download option) ·
Source button (M14-EXT-02 owns its modal) · Hide settings · Preview
focus. Owner feedback triage D88; milestone rules (D73) hold —
UI-only, byte-identical outputs, no new dependencies.

## Constraints decided at triage

- **Build id returns to the chrome** as quiet meta text — a recorded
  reversal of the A13 Project-foot placement, on the owner's call.
  Keep it visually subordinate (code-01/meta, not a heading sibling).
- **Diagnostics cluster stays dev-gated** (`import.meta.env.DEV`) per
  UI-STANDARDS "Diagnostics affordance" — production exposure still
  requires the redaction review. Top-bar placement *improves*
  conformance (the standard prefers an app-shell utility surface).
- **Log download is new**: a "Download log" action beside Copy
  diagnostics, saving the redacted bundle as a file
  (`downloadBlob` precedent). Same redaction path as copy — never the
  raw ring buffer.
- **Hide settings and Preview focus stay two controls** (owner pick:
  distinct functions — persisted layout preference vs session mode).
  Both move into the bar; labels/behaviour unchanged.
- Keyboard/landmark rules: the bar is the existing `header`; controls
  stay real buttons in DOM order; 44 px targets; focus order = visual.

## Done when

The six affordances sit in the bar at 320 px/wide/focus in both
schemes without wrapping chaos (stack/priority decided in-task and
recorded); shell tests + ui-styles invariants green; ui-baseline
tripwire green; evidence section added.
