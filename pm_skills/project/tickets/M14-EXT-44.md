# M14-EXT-44 — Processing order retires; Advanced sunsets

Memo item 8 (sixth look, D112): "lets remove processing order. is
either setting redundant? what are the pros and cons." The owner's
question is answered in D112; the operative summary lives here so
the gate starts informed.

## The assessment (recorded)

- **resize-first** is the product: D3's core lever (resize to the
  stitch grid, then per-pixel work), fast, and the path every
  acceptance invariant binds to.
- **reduce-first** exists as the brief §1 "comparison of two
  processing orders". In practice at stitch-grid sizes: slower
  (per-pixel work at source scale), the palette-index sidecar is
  invalidated (resize-after-reduce ⇒ stats fall back to colours
  **without thread references** — a real capability loss while it is
  active), and the dither pattern is averaged away by the downscale,
  so its look tends toward "dither, then blur". Its one genuine
  value — a softer render character — is better served today by the
  M8 dither surface (five methods + per-family strength), which
  controls softness deliberately instead of as a side effect.
- Verdict recorded at triage: not literally redundant (outputs
  differ), but its UI seat is no longer earned; the owner's removal
  call is sound. Cost: the brief's "comparison" line becomes
  historical — the brief already reads as intent, not feature list.

## The one real design question: loaded files

Project files carry `pipeline.preset`; `reduce-first` files exist.
Three conducts:

- **A (recommended): honour + say so.** Core keeps the preset
  (schema untouched, the EXT-29 kept-in-core precedent); the UI
  offers no edit route; while a loaded reduce-first project is
  active, one visible line states it ("Rendering with the retired
  'match colours first' order, from this project file."). Reopen
  stays byte-identical (the golden guarantee) AND state stays
  visible (recognition over recall) — the only conduct satisfying
  both hard rules. Save round-trips the preset unchanged.
- B: coerce to resize-first on load with an announcement — violates
  reopen-identical; rejected.
- C: honour silently — two identical-looking sessions rendering
  differently; violates visible-state; rejected.
